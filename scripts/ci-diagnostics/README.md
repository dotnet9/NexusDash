# Windows 原生自检诊断

`Windows runtime diagnostics` 仅允许手动触发。两台独立的 Windows 云端 runner 分别执行未改动的 `VerifyWindowsTelemetry` 方法，以及保持相同 25 秒共享预算和全部断言的可观测副本。两者均引用固定的 `v0.1.13` 产品源码，不修改产品、依赖或版本，不创建发布资产。

诊断日志只包含阶段、耗时、命令退出码或超时、输出长度、布尔值与计数。CIM 原始结果、进程名称、命令行、硬件标识和未知异常消息不会写入日志。异常仅记录类型、HResult 和方法名称。该诊断只应运行在一次性云端 runner，不应在用户设备上执行。

`exact` 可确认托管版本是否触发原有断言；`instrumented` 可定位硬件、进程和系统阶段，并观察原始命令预算。两者运行在不同 runner，结果不能当作同一台机器的严格对照。如果托管版本均通过，仍不能排除 NativeAOT 特有问题，需要另行授权对相同源码生成控制台 AOT 诊断产物。

若原始进程校验已失败并保存证据，`instrumented` 才会在同一 runner 后置执行独立服务查询：原过滤条件分别使用 3 秒和 10 秒 CIM 预算，再执行不带过滤的 10 秒查询。每条命令使用新的时间预算和 `-ErrorAction Stop`，仅记录行数、正 PID 行数、查询耗时及异常类型、Category、HResult、原生数值错误码；不记录实际 PID、服务名或异常消息。后置查询不会改变原始失败结果。
