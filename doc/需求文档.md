# NexusDash 产品需求与优化清单

## 产品定位

NexusDash 是面向开发者、运维人员和高级用户的跨平台操作系统资源管理软件。产品优先解决“发现异常进程、理解资源占用、定位网络通信、执行安全处置”这条排障链路。

设计风格参考 Zhijian 的专业工作台：克制、紧凑、信息密度高、长时间使用不疲劳。TaskExplorer 是能力参考对象，但不做简单复刻；NexusDash 的差异化重点是跨平台一致体验、清晰的信息层级、可解释的高风险操作。

## 平台范围

```
- Windows：进程树、进程资源、结束进程/进程树、TCP/UDP 连接归属优先完整。
- Linux：基于 /proc 提供进程与网络连接，普通权限下展示最佳可见范围。
- macOS：基于 ps/lsof 提供首版能力，后续评估 libproc/native 后端提升性能与准确性。
```

## 当前首版闭环

### 进程管理

```
- 展示进程树：PID、父 PID、进程名、CPU、内存、磁盘 I/O、TCP/UDP、GPU。
- 支持搜索：PID、进程名、路径、命令行。
- 支持选择进程、结束进程、结束进程树。
- 进程详情：启动时间、路径、命令行、资源指标。
- Treemap 展示内存占用前列进程，辅助快速发现大户。
```

### 进程 TCP/UDP 通信管理

```
- 选中进程后展示 TCP/UDP 连接明细。
- 展示协议、本地端点、远端端点、连接状态。
- 进程列表展示 TCP/UDP 计数，格式为 TCP/UDP。
- 网络连接刷新不阻塞进程列表刷新。
```

### 基础体验

```
- 标题栏菜单收纳操作、主题、语言。
- 支持黑色/白色主题，所有主界面、表格、页签、状态栏文字必须可读。
- 所有用户可见文本进入 i18n/l10n，首批语言为 zh-CN、zh-Hant、en-US、ja-JP。
- 使用 AtomUI 控件和图标，避免原生控件在主题下出现空白或弱对比度。
- 提供软件 Logo、窗口图标和任务栏图标。
```

## 需求优化优先级

### P0：把“能用”变成“可信”

```
1. 进程列表排序
   - 点击列头按 CPU、内存、磁盘 I/O、TCP/UDP、PID 排序。
   - 默认排序建议为进程树结构优先，允许切换为资源占用排序。
   - 验收：排序后选中态保留，刷新后不跳回随机位置。

2. 表格列宽与横向滚动
   - 支持列宽拖拽，长路径/长进程名截断并提供 Tooltip。
   - 小窗口下保持 PID、进程名、CPU、内存四列优先可见。
   - 验收：1280x820、1060x680 下无文字互相遮挡。

3. 高风险操作确认
   - 结束进程、结束进程树必须弹确认。
   - 弹窗展示进程名、PID、影响范围、权限风险。
   - 验收：取消不执行；失败时显示系统返回原因。

4. 权限与可见性提示
   - 对无法读取路径、命令行、连接归属的进程显示“权限受限”。
   - 提供“以管理员/root 权限重新启动”的入口占位。
   - 验收：不把权限缺失误展示为空数据。

5. 刷新稳定性
   - 进程列表每秒刷新，但滚动位置、展开状态、选中状态保持。
   - 网络采集慢时使用上一帧网络数据，不拖慢进程指标。
   - 验收：连续运行 10 分钟无明显 UI 卡顿。
```

### P1：对齐 TaskExplorer 的核心排障能力

```
1. 连接操作
   - 复制本地端点、复制远端端点、复制整行连接信息。
   - Windows 上评估 TCP 连接断开能力，作为高风险操作处理。
   - 验收：右键菜单可用，断开失败给出原因。

2. 句柄与文件
   - Windows 显示进程打开的文件/句柄；Linux/macOS 显示 fd/lsof 结果。
   - 支持搜索路径、类型、句柄名。
   - 验收：至少能定位“哪个进程占用了某个文件”。

3. 模块/DLL/动态库
   - 展示进程加载模块、路径、版本、签名状态。
   - Windows 优先支持 DLL；Linux/macOS 展示 so/dylib。
   - 验收：选中进程后可看到已加载模块列表。

4. 线程视图
   - 展示线程 ID、CPU 占用、状态、启动地址或可用描述。
   - 验收：CPU 异常进程可进一步定位高占用线程。

5. 服务与启动项
   - Windows 服务与启动项先完整；Linux systemd 服务、macOS LaunchAgent 后续补齐。
   - 验收：能从服务定位到对应进程，能展示启动状态。
```

### P2：专业化与跨平台增强

```
1. 进程时间线
   - 记录选中进程最近 60 秒 CPU、内存、磁盘、网络趋势。
   - 验收：切换进程时右侧详情展示迷你趋势图。

2. 快照与导出
   - 导出当前进程列表、网络连接、选中进程详情为 JSON/CSV。
   - 验收：导出文件包含时间戳、平台、权限状态。

3. 过滤器
   - 支持只看有网络连接、只看高 CPU、只看用户进程、隐藏系统进程。
   - 验收：过滤结果和总数同时展示。

4. 告警与标记
   - 用户可对进程打标记；CPU/内存/连接数超过阈值时提示。
   - 验收：告警不打断用户操作，状态栏给出轻量提示。

5. 主题持久化与语言持久化
   - 记录用户上次选择的主题、语言、窗口尺寸、列宽。
   - 验收：重启后恢复。
```

## 信息架构优化

```
顶部：全局资源概览、搜索、主要处置按钮。
中左：进程树主表，是首屏核心。
下左：Treemap/资源热点，可切换为 CPU/内存/磁盘/网络热点。
右侧：选中进程上下文面板，包含详情、网络、句柄与文件、模块、线程、服务。
底部：刷新状态、选择数量、权限/错误提示。
标题栏菜单：操作、主题、语言、帮助/关于。
```

## 交互细节要求

```
- 表格行高度保持 30-34px，优先保证扫描效率。
- 选中行背景必须明显，但不能压低文字对比度。
- 禁用按钮必须解释原因，例如“未选择进程”或“权限不足”。
- 高风险动作统一使用确认弹窗，不在菜单和主按钮里各做一套逻辑。
- 网络连接、句柄、模块列表都需要空状态文案，区分“无数据”和“权限不足”。
```

## 跨平台能力差异说明

```
- 不同平台不可避免存在字段缺失，UI 必须显示字段状态，而不是简单留空。
- Windows 管理员权限能看到更多命令行、句柄、连接归属。
- Linux 普通用户可能无法读取其他用户进程 fd，需要明确提示。
- macOS lsof 可能较慢，首版应降低刷新频率或使用后台缓存。
```

## 验收标准

```
1. 应用启动后 3 秒内进程列表必须有内容；若采集失败，显示错误原因。
2. 选择任一进程后，右侧详情必须更新。
3. 选择有 TCP/UDP 的进程后，网络页必须展示连接明细。
4. 黑色/白色主题下，主表、页签、弹窗、状态栏文字都可读。
5. 切换 zh-CN、zh-Hant、en-US、ja-JP 后无明显未翻译主流程文本。
6. 结束进程/进程树有确认、有结果、有失败原因。
7. Windows、Linux、macOS 至少完成冒烟测试并记录平台差异。
```

## 近期建议迭代顺序

```
Sprint 1：排序、列宽、确认弹窗、权限提示、主题/语言持久化。
Sprint 2：连接复制、网络过滤、进程详情趋势图、导出 CSV/JSON。
Sprint 3：句柄与文件、模块/DLL、线程视图。
Sprint 4：服务/启动项、连接断开、管理员/root 重新启动。
```
